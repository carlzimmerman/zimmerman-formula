# DF3_fluid_next_gates AMENDMENT A2: post-result, disclosed as such

Written after the first (5/3, 30) N cell printed X-COP held -0.881 with NO EQUILIBRIUM 1.00. kappa = 1/2 FITTED. Not theory closed.

**A ceiling artefact in my solver.** The central-density scan stopped at 1e-8 kg/m^3. For Gamma 5/3 at sigma 30 the most massive X-COP clusters need a centre near that or above, so the scan ran out before reaching fair share and the rows read NO EQUILIBRIUM for the wrong reason. Gamma 5/3 has no Newtonian mass limit, so that label was an artefact. Fix: for Gamma > 4/3 only, the scan runs to 1e-1 kg/m^3 at the same spacing. Gamma <= 4/3 rows are unchanged, bit for bit. Both Gamma 5/3 N cells were rerun with the fix, and the controls with it. The first (5/3, 30) N output was overwritten; its X-COP line is quoted above.

**That doesn't make those cores real.** The fair shares involved sit above the Fermi-gas M_TOV at both sigma for most X-COP clusters, so they read NO EQUILIBRIUM (GR) as the criteria say, whatever the Newtonian solver returns.

**Controls before A1.** The first controls run failed three of my own Lane-Emden lines from a coarse output grid and a wrong test setup for n = 5, not from the solver. I fixed the tests (finer output grid, the n = 5 test shot from a chosen centre), and set the tolerances back to the frozen 1 %. The MUTATE twin first carried the self-gravity factor into the analytic scale, so it couldn't fail; removed before any graded number.

**A second harness artefact, found reading the first tables: the keys couldn't see a compact core.** In the first pass every cell read 10 of 15 keys, the law's own count, Gamma 5/3 included, though its X-COP read -1.27. CRG1's shear harness builds density from dM/dr on a grid that starts at 1 kpc and projects it with log interpolation, so mass inside about 8 kpc is under-counted and mass inside 1 kpc is lost entirely (`df3g_keycheck.py`: a central point mass returns 1e-14 of its Delta Sigma). Fix, reading N only: before projection, fluid mass inside 20 kpc is redistributed as a Plummer of 8 kpc with the same M(<20 kpc). That leaves M_2D(<R) and Sigma(R) unchanged at R >= 20 kpc, and the key radii start at 180 kpc. Known answer, in `df3g_keycheck.json`: the softened point mass returns 0.997 of the resolved profile's Delta Sigma R^2 at 0.18-2.6 Mpc. The keys were rerun for all five N cells and the law; the first pass is kept in each cell's JSON as `K_first_pass_lost_core`. The law's keys don't change (no fluid). Gamma <= 1 cells barely change, since their held fluid is diffuse. The S keys READ from the other lane may carry the same under-count for its Gamma 5/3 cores; I haven't checked their numbers and don't edit that lane.
