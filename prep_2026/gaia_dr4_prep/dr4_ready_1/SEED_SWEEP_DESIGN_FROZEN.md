## The seed set k (k = 0 is the frozen builder; SEED = `build_catalog.SEED` = 20261202, read from the module)
| use | builder site | seed in build k |
|---|---|---|
| stage-E shifted realisations | `pair_search(..., shift=True, seed=r + 1)`, per-block seeds `seed*1000 + block` (400 blocks) | `r + 1 + 100 k` |
| stage-E half-mask | `default_rng(SEED)` inside `_e()` | `SEED + k` |

Changed IN MEMORY: the source text of `main()`'s `_e` / `_f` closures and of `r_chance` is extracted with `inspect`, given exactly these substitutions (each asserted to occur the expected number of times), and executed in a namespace; the frozen file is never written. **Stages A to D are shared** (the inputs); E, F, G are recomputed per build in a gitignored per-build directory `<extract>/seed_k<k>/`; each build has its own correlation cache `seed_k<k>/stage_G_corr_<variant>.npz` (primed from the primary's file, never written back to it).

## The fit (the registered path; the spread is build-only)
**Revised before this file was committed, after measuring the pipeline CLI (one `wide_binary_pipeline.py --catalog <csv>` run on the 6,210-pair DR3 catalogue takes 30 s; it printed `catalog [a0 canonical] gamma_inf = 1.0750 +- 0.0550 (chi2/bin=2.13, bins=6, kappa=1.0232)` and `catalog [a0 alt footing] gamma_inf = 1.0775 +- 0.0512 (... kappa=1.0247)`).** The fit of every build is therefore the pipeline's OWN `--catalog` run as a subprocess (exactly the registered path and seed 20261216, the same on DR3 and on release day; its forward model is the pipeline's DR4-noise one, so on DR3 data this is a code-path test), with the printed `gamma_inf = g +- s (chi2/bin=.., bins=.., kappa=k)` lines parsed for both footings and the `[7(e)]` risk line (kappa window, 1.23 edge) recorded verbatim. No in-process replica of `run_fit` is written (it returns no kappa; the subprocess prints it). **Fit-only control (rev 1 of the draft, literal):** the k = 0 catalogue refitted by the same run with `--seed 20261216 + j`, j = 1..K (in the pipeline that seed feeds both the forward-model population and the bootstrap, so this control carries both). WP2-gamma's in-process numbers (DR3-noise forward model, bootstrap-only control) are a different fit path and are not reproduced here. sigma_build = SD (ddof = 1) of gamma-hat over the K + 1 builds, per footing; reported with the mean sigma_fit, SD/sigma_fit, the fit-only SD and kappa per build.

## Controls (all reported; a failure is reported plainly)
- **C1 byte identity.** The driver with no new option and with `--seed-offset 0` reproduces the reference DR3 CSV (sha256 prefix `6fff64d964ebaa72`); the driver's existing self-test S0 to S6 still passes.
- **C2 E/F rebuild fidelity.** `rebuild_EF(k = 0)` at the builder's N_SHIFT = 30 reproduces `dr3_extract/stage_E.npz` and `stage_F.npz` exactly (`np.array_equal` on every key). (Run in the background; about 15 min.)
- **C3 seed sets.** For builds k = 0..10 at N_SHIFT = 30 and 400 blocks the stage-E per-block seeds are all distinct (0 duplicates of 132,000); a text scan of `build_catalog.py` finds exactly the expected random-draw sites (`default_rng(` at the block seed, `r_chance`, `vt_error_mc`, the stage-E mask; `seed=r + 1` once) and fails if the builder gains another.
- **C4 G seed explicit.** `vt_error_mc` with seed SEED + k differs from the default call for k >= 1 and equals it for k = 0 on a slice of pairs; patching `B.SEED` alone leaves the default-seeded stage-G output unchanged (the pitfall, tested).
- **C5 hash guard.** The builder's sha256 equals the frozen value before and after a build; a planted one-character edit of a temporary copy makes the guard raise.
- **C6 cache paths.** Per-build correlation caches have distinct names per k, none equals the builder's shared `stage_G_corr.npz`, and the k = 0 path equals the driver's current path.
- **C7 fit parser.** The parser reproduces, on the pipeline's saved stdout for the reference CSV, gamma-hat, sigma_fit and kappa of both footings (canonical 1.0750 / 0.0550 / 1.0232; alt 1.0775 / 0.0512 / 1.0247), and raises when a footing line is missing.
- **C8 fit determinism.** Two pipeline runs on the same CSV with the same seed give identical parsed values; a run with `--seed 20261217` differs in sigma_fit or gamma-hat (the forward model and the bootstrap are live).
- **C9 MUTATE (`MUTATE=1`).** K + 1 = 3 builds all run with the IDENTICAL seed set (k forced to 0): the final CSVs have identical sha256 and sigma_build = 0 exactly on both footings. The un-mutated stage-G-only sweep (k = 0, 1, 2) gives different per-build sha256 and sigma_build > 0, and the planted-difference count equals a direct set comparison.
- **C10 manifest.** The seed list is written BEFORE any build; afterwards the file carries the builder hash before/after, the K actually run, each build's CSV sha256, pair count, uncovered-correlation count, gamma-hat, sigma_fit and kappa on both footings, the fit-only control values, and sigma_build (ddof = 1).

## Not built here (stated before the code)
**Ladder-variant shifts.** `FROZEN_LADDER` in the pipeline is a printed string and `frozen_cuts` implements only the primary cut list; no ladder catalogue code exists. The revision's per-build ladder shifts need new code whose rung definitions are not fully fixed in the record (RV-screened subsample; NSS-off needs a superset table). This build implements only the rungs that are post-filters of a build's final table with the columns the CSV carries (`R_chance` < 0.001; separation 3 to 20 kAU), reported as such; RUWE 1.2, RV-screened and NSS-off are flagged NOT IMPLEMENTED. **A machine-readable edge table** for the seed-sensitivity label is a separate file to be checked against the amendments' text.

## Limits (written before the run)
DR3 stage-G-only sweeps flip far fewer pairs than full E/F/G rebuilds (the tests use stage-G-only builds for speed and the full rebuild only for C2); a stage-G-only sigma_build is NOT the WP2-gamma quantity. The correlation coverage of the DR3 caches is limited (uncovered ids get zero correlation, counted and reported per build).

## Addendum 1 (written after the code existed but BEFORE any test of it ran; additions only, no control above is weakened)
Four controls are added, three of which use WP2-gamma's independent earlier implementation (its ten per-build directories `dr3_extract/wp2_gamma_k`, k = 0..9, hold each build's `stage_E.npz`, `stage_F.npz` and `final.csv`, built with the SAME seed-set definition by in-memory text substitution of the wp2_variant machinery):
- **C2b E/F seeds at k = 1.** `rebuild_EF(k = 1)` at N_SHIFT = 30 reproduces `wp2_gamma_1/stage_E.npz` and `stage_F.npz` exactly (every key). (FULL; about 15 min.)
- **C6b delta fetch.** The per-build correlation fetch queries only the ids its cache (primed from the primary's file, read-only) lacks, merges into the build's own file, leaves the primary's file byte-identical, and a repeat queries nothing (tested with an injected query function, no network).
- **C11 full-path smoke.** k = 0 and k = 1 both rebuilt through E, F and G at N_SHIFT = 3 and fitted by the pipeline CLI: the builds differ, the fits parse, the builder hash holds. (FULL.)
- **C12 driver fidelity.** For k = 0..9 the driver with `--seed-offset k --stage-dir dr3_extract/wp2_gamma_k` reproduces `wp2_gamma_k/final.csv` BYTE FOR BYTE (the G seed SEED + k, explicit; the same offline correlations; the same cuts), and the per-build uncovered-correlation count is recorded (item 9 of the read-through).
Also fixed before running: the fit-only control reported is the SD over the registered fit and the K controls (K + 1 values) as well as the K controls alone; the stage-E per-k rebuild directory name carries N_SHIFT so a smoke build can never be reused as a real one.
