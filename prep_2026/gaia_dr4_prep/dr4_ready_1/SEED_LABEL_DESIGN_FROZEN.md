## The label (draft rev 2 (c)-(e))
sigma_build = SD (ddof = 1) of gamma-hat over a G-ONLY sweep of K_G builds (k = 0 the primary; build k seeds stage G SEED + k, passed explicitly; A-F the primary's; the fit on the registered path, seed 20261216); **at least 10 builds are required before the label applies** (fewer: 'NOT APPLICABLE (K < 10)'); K_G >= 50 recommended. The SD of a full E-G rebuild sweep (K_F = 3 to 10, stage-E shifts r + 1 + 100 k) is reported BESIDE it. width = max(sigma_build, 0.3 sigma_fit,primary). **If the primary gamma-hat (footing by footing; canonical decides) lies within `width` of any edge, the verdict is reported with the label 'seed-sensitive', stating for that edge how many of the K + 1 builds fall below and above it** (strictly below / at or above); the full-rebuild builds' counts are reported beside. Stability conditions (kappa window, each implemented ladder rung's shift below 1 sigma_fit) are evaluated for every build; **any condition whose pass/fail status differs across builds is labelled 'seed-sensitive' in the same way.** The primary's verdict is the one recorded; labels are added, never substituted.

## Controls (all reported; a failure is reported plainly)
- **L1 extraction.** The table's in-force entries equal the pipeline attributes, every attribute of the three families is classified, `GAMMA_MG` 1.137 is excluded, each excluded constant's reason string occurs in the pipeline source, the pipeline's sha256 equals the frozen value, sigma_sys 0.02 is found in the pre-registration text; a planted unclassified constant (a temporary copy of the pipeline with one extra `GAMMA_PLANT = 1.5`) makes the extraction raise.
- **L2 edges.** At a hand-computed sigma_tot (sigma_fit 0.019 gives sigma_tot 0.02759) the z-rule edges around 1.0000 are 0.9172, 0.9448, 1.0552, 1.0828 (checked by hand) and the table's hard edges appear once per footing.
- **L3 label.** A primary gamma-hat placed 0.5 width from an edge is labelled, with the below/above counts of a planted set of builds equal to a direct count; placed 2 widths from every edge it is not labelled.
- **L4 the width rule.** With sigma_build below 0.3 sigma_fit the width is 0.3 sigma_fit; above it, sigma_build; a planted gamma-hat between the two widths flips the label accordingly.
- **L5 stability.** A planted set of builds with kappa crossing 1.05 in some builds is flagged; one with all kappa inside is not; a planted ladder rung whose shift crosses 1 sigma_fit in some builds is flagged.
- **L6 K requirement.** Fewer than 10 G-only builds gives 'NOT APPLICABLE (K < 10)' and no label.
- **L7 MUTATE.** The same planted case evaluated with the excluded stale target 1.137 added to the table changes the outcome (the label bites on the list).
- **L8 DR3 rehearsal.** Run on the G-only 51-build manifest and the full-rebuild manifest of the DR3 sweeps (Q-G50; `seed_sweep_manifest_g50.json`) if present: the report is written, the edges within the width are listed. A code-path demonstration, never a result.

## Limits (written before the run)
The edge list is what the frozen code carries; edges that exist only in the amendments' text (the chain ceiling) are NOT in the table, and the label cannot see them. Canonical decides; the alt-footing label is reported beside. The label answers 'is the primary near an edge relative to the build noise', not 'is the verdict right'.
