## 2. Quantities (all REPORTED, none scored)
- **Q1 candidate-level flags (the DIRECT effect of cut 13):** for each path the number of the 10,231 candidates flagged, split final / delta; the pairs flagged by a cones path but not by its matched extract path, listed with their pair index, projected separation, and the number of cone neighbours; the overlaps.
- **Q2 final sets (what the driver writes):** for each path the number of final pairs and its sha256. For each matched pair: D_out = the pairs of the extract path's final set that the cones path flags at cut 13 (they cannot be in the cones path's final set); flips = (|F_ext minus F_cones| + |F_cones minus F_ext|) / 2 (half the symmetric difference, the PLAN.md definition); the remainder flips − D_out is the stage-G Monte-Carlo re-roll component. **NULL (the array-change reference):** 30 draws, seeds 20261230 + i, of the extract path's flags PLUS n_extra random additional candidates flagged (n_extra = the number of candidates the cones path flags that the extract path does not, per matched pair; the extra ones drawn among the candidates the extract path does not flag), run through the driver: the mean, SD and the 16 to 84 % interval of flips, with the cones path's flips placed against them.
- **Q3 fit effect:** `wide_binary_pipeline.py --catalog <csv> --seed 20261216` (the registered path) on the final CSV of each of: extract-builder (the primary), extract-literal, cones-literal, cones-orbit, and on the first 10 null draws of the literal pair: gamma-hat and sigma_fit, both footings, the pipeline's self-test status. The shift of gamma-hat from the matched extract path in units of sigma_fit (canonical decides; alt beside it), against the build-to-build SD of 0.3 to 0.44 sigma_fit (DR3 G-only sweeps) and against the null's own SD of the shift.

## 4. Controls (each can fail; a failure is reported plainly and the quantities of Q1 to Q3 are then not interpreted)
- **X0 plumbing:** cones built from the extract itself for ALL 10,231 candidates (`build_extract_cones`) reproduce the flags of `extract-literal` and `extract-builder` exactly.
- **X1 coverage:** the combined table covers all 10,231 candidates (`n_missing = 0`) and a table built from the final-pair file alone raises `ConeCoverageError` naming 4,021 of 10,231. **X1b per-pair completeness:** every local-extract source inside the exact cone of each candidate is among the cone rows keyed to THAT pair in the combined table (this catches a wrong pair_id mapping, which the all-at-once geometric evaluation cannot see).
- **X2 superset:** flags(extract path) is a subset of flags(matched cones path), per criterion (the cones contain every extract source, and the criteria are existence tests); a violation means a data or code inconsistency.
- **X3 column agreement:** for every source of the fetched files that is also in stage A, the nine numeric columns agree (relative difference <= 1e-6, NaNs matching); thresholds fixed here.
- **X4 planted neighbours:** into the cone of a delta pair the real cones-literal does not flag, a kinematic twin of the primary (same parallax and proper motion and errors, 3.6 arcsec away, G = 15) is planted in a COPY of the table: the pair must now be flagged; a planted star with a third of the parallax and a different proper motion must NOT flag it.
- **MUTATE=1:** the delta file is left out: X1 must FAIL (the guard raises). **MUTATE=2:** the parallax of every delta row is shifted by 1e-3 mas: X3 must FAIL. **MUTATE=3:** the delta pair ids are shifted by one: X1b must FAIL. MUTATE runs execute the controls only and write separate files.
- **STAND-IN dry run (before the real delta exists):** the delta cones are built from the extract (`build_extract_cones` on the delta pairs) and the script is run end to end: the cones paths must give, on the delta pairs, the flags of the extract paths, and on the final pairs the WP1 result (literal 2, orbit 0); nothing from it is a result, and its outputs are named `_standin`.

## 5. Rules
The first real run is kept as it is, with the numbers as printed; a rerun after a fix is a new file and the first run stays beside it. DR3 is a rehearsal: nothing here is a statement about DR4 or about gamma. The delta file must pass `local_extract_sources_missing_from_fetch = 0` in its manifest before this analysis is run on it.

## 6. Limits
The comparison is for ONE build (seed offset 0); the flips between the extract path and the cones path say what the real all-source search changes against the stand-in, not what it will change on DR4 (a different density, a different candidate set). The extract is a thinned subset of DR3, so the extract path misses most neighbours by construction; the MC re-roll component is a property of the builder, not of cut 13. Nothing here validates the criterion of cut 13 itself.
