## 2. What READY means (per target; all of R1–R5 must hold)
- **R1 hashes.** sha256 of the sealed JSON equals PREDICTIONS_HASH.txt; every file in §1 is byte-identical to its freezing commit
  (computed with `git show <commit>:<path> | shasum -a 256` and against the working tree); CFG806's criteria hash equals the
  value quoted in its ID notes (bc56aa71…).
- **R2 reproduction.** The harness's copy of CFG571's functions reproduces every sealed number for the target (logVbar2R_G,
  logMgas for both gas shapes, FLOOR flags, both footings, all four models) to ≤ 1e-12 dex. The functions are obtained by executing
  only the text of `cfg571_prereg.py` above its `# ---- controls ----` line in a private namespace (a plain `import` would run the
  whole script, rewrite its results JSON and call `sys.exit`). Nothing is written into any frozen lane (checked: K5).
- **R3 transcription.** Every cell of the plan's §2 table (CFG806 §2 for U4, CFG809 §2 for GS4) matches the sealed JSON within
  0.005 dex (two-decimal rounding); FLOOR cells identical.
- **R4 harness.** One script per target in this directory takes the future data products as paths (FITS cube; for GS4 also the
  continuum image) and prints the frozen classes; a second entry point scores a measured-quantities JSON. Every gate and reading
  of the plan is implemented. Every step the plan leaves under-specified gets a declared harness default that is printed as a
  flag and listed in the README; no frozen rule is changed.
- **R5 mock dry-runs.** MOCK cubes are generated by the harness itself (seed 942; FITS `OBJECT = 'MOCK'`; file names contain
  `MOCK`; written to a scratch directory and never committed; their sha256 is recorded), then read back through the same path as
  real data, from FITS to class. Mock noise is chosen for clean detections and is NOT the archive sensitivity (see R7).
