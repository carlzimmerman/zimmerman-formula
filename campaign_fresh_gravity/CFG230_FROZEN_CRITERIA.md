## 1. The question and its scope

**The missing object** (GAPS_1_2_JOINT_STATUS, TEN_DOORS_GATES): a mechanism that makes a cold conserved component's density inside a bound system satisfy the exact target of CFG44,
C(r) = rho_c r^3 g_tot = (a0 / 4 pi) M_b(<r), with g_tot = nu(g_N/a0) g_N,
a0 = kappa c sqrt(G rho_Lambda), kappa = 1/2 FITTED, while behaving as plain CDM through recombination and linear growth. For the P2 kernel nu = sqrt(1 + a0/g_N) and a point mass: rho_c = a0 / (4 pi G r sqrt(1 + x^2)), M_c(<r) = M (sqrt(1 + x^2) - 1), x = r/r_M, r_M = sqrt(G M / a0). The kernel is a declared choice (DOOR11 Erratum 1: P2 primary; nu_mono and the simple kernel are reports, not the target).

**What CFG230 does.** It turns the recorded failures of the scored doors (kernel/nonlocal, Verlinde, dipolar DM, superfluid DM, f(E,L), secondary infall, fuzzy DM, interacting vacuum, Deser-Woodard, mimetic, and door 11's 11A, 11B', 11C-a, b, c, d) into a requirements list: the smallest set of necessary properties that a mechanism must have. Each requirement is stated as an inequality or a structural condition, tagged with the doors that motivate it, and carries a check that phase 2 will run.

**What a requirement is not.** A necessary condition read off failures of classes that were scored. Not shown sufficient. Not shown jointly satisfiable, and not shown jointly unsatisfiable (4.5 maps only pairwise pincers that lanes already computed). Conditional on candidate B's frame: the a0-Lambda tie, a cold conserved fluid that IS the law's dark density, the P2 (declared) kernel, and G1-G8 as frozen. R04-R06 presuppose the fluid target; for a law-level class with no fluid they are N (not applicable), and that class must say where the cluster and CMB cold mass comes from.

### 3.3 Classification and evidence grade (frozen)
- **THEOREM.** Holds for a stated class regardless of parameters; the class hypotheses must be written next to it. Sub-grade: **L** = Lean-certified at commit b8d8b1ba5 or the earlier ChainCert commits (table 2.2), with the premises the README states (axioms-only certificate; the pending batch is excluded); **S+R** = derived symbolically in the lane and re-derived symbolically by an independent referee; **S** = symbolic or analytic in-lane only.
- **SCOPED-NUMERICAL.** Holds in the frozen class and scan. **N+R** = reproduced by independent code; **N** = lane only (an orchestrator in-place re-run checks reproducibility, not independence).
- **DECLARED-CHOICE-DEPENDENT.** Moves with a declared choice (kernel P2 versus nu_mono, the G1 band, the "same constants at every mass" clause, the r_ta convention, a declared placeholder bound, a continuation branch, ownership as B's rule). The entry names the choice and cites the referee finding that exposes it.
- **M.** Literature recalled from memory; can never support "must".

## 4. The derived requirements list: method and the twelve requirements

### 4.1 Method (frozen)
1. Transcribe each row's obstruction (3.6) into the record.
2. Rewrite it as a property of the mechanism, dropping the mechanism's name.
3. Merge obstructions stating the same property into one requirement; keep a requirement only if at least one obstruction states it.
4. Give each requirement the weakest grade among its LOAD-BEARING supporting entries (9.1). A requirement stronger than its weakest load-bearing entry is rewritten or split.
5. List motivating rows, class, the check phase 2 will run, and the expected value (HAND, 4.4).
6. Build the incidence matrix (5.1). Compute (a) the hard-core set H = requirements no scored row meets with code P; (b) the minimum set cover (exhaustive over 2^12 subsets) of failed rows by requirements they violate; (c) each requirement's support (rows with F) and whether it rests on a single row; (d) fragile requirements (support <= 2 and no THEOREM core).
7. Map pairwise pincers only where a lane already computed a numerical gap (4.5), plus the one P/P_cap comparison derived from the Lean README.

### 9.1 Disagreement, unsupported entries, and the strength rule (frozen)
- **DISAGREEMENT** if any of: (i) a quoted number is not found in its cited source within 1% (or one unit in the last printed digit); (ii) my recomputation differs from the lane's by more than the per-check tolerance stated in the script header (default 1% for closed forms, 5% for numerics with a declared convention); (iii) a referee status is Q and the qualification touches the load-bearing number (the entry is downgraded one grade unless the qualification is only a label); (iv) two lanes give different values for the same quantity (for example the tail 0.282 versus 0.47 by kernel, P2 versus the simple interpolating function per DOOR11 Erratum 1, the D08 pressure spread 32-353x versus 32-272x, or GATES_STATUS row 5.12's "up to 2%" versus CFG44's 1.46). - **UNSUPPORTED** if any of: the commit is not a git object; the anchor string is absent from the cited file; the entry rests on LEDGER prose with no committed script; the entry is a MEMORY literature statement; the entry rests on a lane flagged as run only by its own lane and the number is load-bearing for a THEOREM claim; the entry cites the pending Lean batch. An UNSUPPORTED entry cannot carry a requirement above DECLARED-CHOICE/M.
- **Strength rule.** A requirement may not be stated more strongly than its weakest load-bearing evidence class. "Must, for class C" needs THEOREM at grade S or better; "in the frozen class the mechanism fails" is the strongest wording for SCOPED-NUMERICAL; "moves with X" for DECLARED-CHOICE. A scoped no-go is not a theorem. A referee reproduction is not a proof and does not upgrade a class by itself. A Lean certificate certifies the statement and premises it states (for the no-EFE and ownership items: pointwise laws only, the ownership rule a postulate, PDE theories not formalised). A requirement whose only support is a single row and is not THEOREM is labelled FRAGILE. The synthesis never says a requirement set is jointly unsatisfiable or sufficient, and never says any data favour or disfavour the framework.
