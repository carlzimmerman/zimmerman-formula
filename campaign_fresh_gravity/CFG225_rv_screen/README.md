# CFG225 — EXPLORATORY: how much of the DR3 γ̂ does the frozen radial-velocity screen move?

> **EXPLORATORY. The DR3 γ̂ was already seen** (pre-registration §1.6: 1.205 ± 0.035, El-Badry-based, 10,624 pairs). **Amendment 7(e): DR3 numbers are code-path tests, never results. No verdict words; not a test of any law.** Gaia DR3 radial velocities (about 1 to 5 km/s) cannot measure orbits, only screen triples. Criteria `FROZEN_CRITERIA.md` (fd4a2a7a7), committed before any RV value was read. The primary uses Gaia DR3's own RVs already in the extract (no download); the DESI top-up is a later variant that needs the owner's go.

## Bottom line
- **The frozen screen (cut 11) flags 135 of the 3,886 RV-matched pairs = 3.47% (2.13% of the 6,342-pair BEFORE set)**, in line with the ~3.5% loss the pre-registration quotes for Banik+24 at DR3. The BEFORE set is the frozen builder's real-settings build (N_SHIFT = 30, frozen seeds) with cut 11 disabled; 3,886 of its 6,342 pairs (61.3%) carry both Gaia RVs. The threshold is set by the RV errors, not the orbital speeds: median σ_dRV 2.85 km/s, v_c 0.57 km/s, threshold 8.56 km/s, median |dRV| of all S_RV pairs 1.34 km/s, of the flagged pairs 24.0 km/s.
- **The change in γ̂ attributable to the screen, on the same subsample, is not resolved:** canonical footing 1.1050 ± 0.0662 → 1.1125 ± 0.0662, change **+0.0075** (paired-bootstrap SD 0.0185; 0.11 σ_fit; 0.41 SD); alt footing 1.0950 ± 0.0587 → 1.1050 ± 0.0612, change **+0.0100** (SD 0.0239; 0.17 σ_fit; 0.42 SD). Whole build: 1.1125 → 1.1200 (canonical) and 1.0750 → 1.0800 (alt) with the screen applied where both RVs exist. The pipeline's γ̂ grid step is 0.0025, so these changes are three to four steps. The 135 flagged pairs alone cannot be fitted (the pipeline's binned fit has no admissible grid point at that N).
- **What it says, no more:** RV-detectable triples are about 3.5% of the RV-matched pairs and removing them moves this build's γ̂ by about 0.01, below what a single sample at this N resolves. It does not address triples whose dRV is below Gaia's RV precision (the orbital ceiling is about 1.4 km/s), nor the 39% of pairs without two RVs.

## Controls (`cfg225_rv_screen.out`: 3 of 4 pass; `_MUTATE.out` pass) and one failure, stated plainly
- **C0 PASS** (the in-memory arrays equal `ingest_csv`). **C1 PASS:** the post hoc flags reproduce the builder's own cut exactly (`frozen_cuts` with the RV columns enabled keeps exactly the 6,207 unflagged pairs). **C2 PASS:** planted triples (10% of the unflagged S_RV pairs, dRV offset N(0, 3 km/s), 20 repeats): flagged fraction 0.1404 against the analytic 0.1426 (SE 0.0034). **MUTATE PASS:** thresholds to infinity flag nothing and Δγ̂ = 0 exactly.
- **C3 FAIL:** with planted plane-of-sky offsets N(0, 3 km/s) on the same pairs, the planted γ̂ shift is −0.052 ± 0.022 (canonical) and −0.048 ± 0.018 (alt), the screen removes only the 14% of the planted pairs it can flag, and the screened shift is smaller than the contaminated shift in 65% and 40% of the 20 repeats against the frozen 90%. **The control cannot show the screen's effect at this N:** the estimator's own noise (about 0.02) is comparable to the planted shift, and **post hoc larger offsets make the planted shift vanish** (σ = 10 km/s: −0.013 ± 0.020 with 44% flagged; σ = 30 km/s: −0.006 ± 0.019 with 73% flagged), i.e. the median-based γ̂ is insensitive to a random 10% velocity contamination here. So the small measured change is not evidence that the screen cannot matter; it is evidence that γ̂ at this N does not respond to it at the level this lane can resolve.
- The first run crashed on the flagged-only fit (kept as `cfg225_rv_screen_firstrun_crashed.out`; the fit is now guarded and its failure reported); the run before the post hoc block is kept as `cfg225_rv_screen_beforeposthoc.out`.
